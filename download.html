Download

Find and download the products with fesmdata.jl

The products are downloaded with fesmdata.jl, a Julia script of FesmData, which puts every file in a fixed layout and checks it against its checksum. Single files can also be downloaded without it (see Single files).

Get the tool

You need Julia (a recent version; no packages to install) and a copy of FesmData. All commands are run from its folder.

git clone https://github.com/fesmc/FesmData.git
cd FesmData
julia fesmdata.jl help

git pull updates it, and with it the list of the released products.

Where the data go

The environment variable FESMDATA sets the folder for the data, e.g. in your ~/.bashrc:

export FESMDATA=/path/to/fesmdata

On Levante and Albedo, source shared/machines/<machine>.env sets it to the shared folder of the project, where the products usually are already (see Machines and storage). On macOS or Windows, do not put it next to the FesmData folder as fesmdata: on a case-insensitive file system, that is FesmData itself.

Every file goes to $FESMDATA/<Domain>/<GRID>/: one folder per domain, and in it one folder per grid with all datasets on that grid. A grid folder thus holds everything a model needs on that grid, and can be copied as a whole:

$FESMDATA/
  Antarctica/
    ANT-8KM/
      grid_ANT-8KM.txt                 grid description (cdo), of the dataset Grids
      ANT-8KM_grid.nc                  x, y, lon, lat and area of the cells, of Grids
      ANT-8KM_TOPO-BedMachine-v4.nc    a product of the dataset Topo
      ANT-8KM_TOPO-Bedmap3.nc
      ANT-8KM_GHF-Lucazeau2019.nc      a product of the dataset GHF
      ...
    ANT-16KM/
  Greenland/
    GRL-4KM/
  ...
  Records/
    IceCores/
      IceCores-Kindler2014.nc          a product of the records dataset IceCores
      IceCores-Kindler2014.txt         its text form

Domains are named after their folder (Antarctica, Greenland, Thwaites, Patagonia, …), grids after the key of their domain and their resolution (ANT-8KM, GRL-500M, DDG-25M); a grid name thus also gives its domain. See Domains and grids (or julia fesmdata.jl domains) for all domains and grids (julia fesmdata.jl where <lon> <lat>: those containing a point, with their datasets), and Products for what is released on each.

Find what is there

julia fesmdata.jl list                     # all released datasets on all domains
julia fesmdata.jl list Topo                # a dataset on all its domains (or a domain)
julia fesmdata.jl list Antarctica Topo     # a dataset on a domain: its grids and
                                           # files, their sizes, and which are here
julia fesmdata.jl list ANT-8KM             # everything on a grid

The arguments can be given in any order. list also shows the products that nests and crops get by cropping (see Nests and crops).

To find products by what they are rather than by dataset, search looks for terms in the names of the products and their files, their sources (with the titles, authors and references of their READMEs), their variables (where the definitions list them) and the domains they are released on, ignoring case and accents; a product must contain all terms:

julia fesmdata.jl search Montoya           # the products from Montoya and Levermann (2008)
julia fesmdata.jl search ghf Antarctica    # heat flow products released on Antarctica

Products not released yet are listed too, as (not released).

Download what you need

julia fesmdata.jl fetch Topo ANT-8KM            # one grid
julia fesmdata.jl fetch Topo ANT-8KM ANT-16KM   # several grids
julia fesmdata.jl fetch Antarctica Topo         # all grids of a domain
julia fesmdata.jl fetch IceCores Records        # a records dataset

fetch needs the dataset, and a domain or grids (in any order). A grid name implies its domain, so the domain can be left out when grids are given.

path prints the paths of the downloaded files of a dataset, one per line, for scripts and viewers; products can be named to keep only theirs (the files missing are counted on stderr):

julia fesmdata.jl path Topo ANT-8KM                  # all products of Topo on a grid
ncview $(julia fesmdata.jl path Topo ANT-8KM BedMachine-v4)

Nests and crops

The thematic datasets (those made by remapping: GHF, Velocity, SMB, Atmosphere, …) are released once, on the domain or crop that has them, and not again on the nests and crops inside it (e.g. Thwaites, a crop of Antarctica, or Jakobshavn, a nest of GreenlandPaleo inside its crop Greenland); a nest or crop is released with its own products only (e.g. Topo, Regions). fetch makes the others there on demand, by cropping them:

julia fesmdata.jl list Jakobshavn          # its datasets, and those by cropping
julia fesmdata.jl list Jakobshavn SMB      # the grids and files that fetch makes
julia fesmdata.jl fetch SMB Jakobshavn     # all grids
julia fesmdata.jl fetch SMB JAK-4KM        # one grid

A nest or crop gets, for each thematic dataset, its own products; those of its parent domain that it does not have; and those of the crops of its parent domain that contain it (e.g. Greenland for the nests of GreenlandPaleo: MAR, Joughin2018, …) that neither has (list shows where each comes from). fetch downloads the files of these products (e.g. Greenland/SMB, to $FESMDATA/Greenland/), and cuts each to the nest or crop, as $FESMDATA/<Domain>/<GRID>/<GRID>_<NAME>.nc with the grid files:

  • at a resolution of the nest or crop, on its own grid (e.g. JAK-1KM, next to its Topo and Regions, with the grid files of the grid from Grids);
  • at the other resolutions, on the cells of the domain grids that overlap the nest or crop (e.g. JAK-4KM, the same cells from the parent and from a crop, which lie on the parent grids).

A grid of a crop that does not cover the nest or crop is skipped, with a message (no partial crops). The crops are exact subsets of the files they are cut from (all variables, attributes and compression as they are), and record that file and its cells in their global attributes (cropped_from, cropped_from_checksum, cropped_from_release, cropped_index_xc and cropped_index_yc, 1-based). Running fetch again keeps the crops of the current files, and makes them again after a new release. A grid of the nest or crop whose released files are on another grid than in shared/domains.toml (a release made before the grid changed) stops the cropping, until it is released again. Cropping needs a few Julia packages (NCDatasets, FesmUtils), which fetch installs on first use.

Mirror everything

To keep a copy of all products on a machine (or of a dataset or a domain):

julia fesmdata.jl mirror                # everything
julia fesmdata.jl mirror Topo           # one dataset
julia fesmdata.jl mirror Antarctica     # one domain

It first checks the files present, shows what is to download or update and its size, and asks once. Run it again after new releases to update the copy: only new and changed files are downloaded (--yes skips the question, e.g. in a job). mirror also makes the products of the active nests and crops by cropping (as fetch, see Nests and crops), e.g. Stratigraphy on Greenland from GreenlandPaleo; crops already made from the current files are kept.

Archives and other folders

--dir=<folder> lists, fetches or mirrors in <folder>/<Domain>/<GRID>/ instead of $FESMDATA (FESMDATA need not be set); fetch --dir writes the crops there too. Only the latest release of each dataset is kept on Helmholtz Codebase, so to keep the releases in use before updating, mirror them into a folder first:

julia fesmdata.jl mirror --dir=/work/ba1442/fesmdata-archive/2026-10-12
julia fesmdata.jl mirror

Files already in $FESMDATA at the same release (checksums) are hard linked from there (no extra space; copied on another file system, or with --copy), the others downloaded, and the registry files of the released datasets go to <folder>/registry/, as the list of what the folder holds. Updates of $FESMDATA write new files, so the hard links keep the archived ones; tools that change files in place (e.g. ncatted) would change both: use --copy for an archive next to files that may be changed in place. Running mirror --dir again on an archive updates it to the latest releases. Earlier releases still in use are kept in such archives on the HPC systems.

Checksums and updates

Every file is checked against its checksum (sha256) after download. Files already present are kept if they are of the release, and replaced if they are of an earlier release (fetch and mirror update them); a file changed locally (not of a release) stops the download, unless --overwrite is given. list --outdated checks the files already present (of all datasets, or of a dataset, domain or grids) and lists those of earlier releases or changed locally, with the fetch commands to update them:

julia fesmdata.jl list --outdated                # everything in $FESMDATA
julia fesmdata.jl list Antarctica --outdated     # one domain

Versions and citation

Each release of a dataset has a version (e.g. Topo 2.2.0, tag topo-v2.2.0 of FesmData), shown on the Products page and by list. Every file records how it was made in its global attributes (fesmdata_version, fesmdata_commit, history), and the sources it was made from. Please cite the original datasets (see the page of each dataset), and the DOI of the release where there is one (releases can be archived on Zenodo). cite shows where the references of products are: the README of each source (references and licence), the README of the dataset, and the DOIs of the releases:

julia fesmdata.jl cite Paleoclimate CLIMBER3a-present   # one product (or several)
julia fesmdata.jl cite GHF                              # all products of a dataset

Single files

Single files can also be downloaded without the tool, from the end of the page of each dataset (Downloads) or from Helmholtz Codebase, one package per domain, dataset and grid. Download the grid files of the grid too (grid_<GRID>.txt, <GRID>_grid.nc), listed under Grid files.
